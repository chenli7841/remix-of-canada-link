# 批次账单统一规则（本地版本，尚未部署）

## 原来的不一致来源

1. 批次显示按箱、托盘、运单和批次费用汇总；确认生成账单却另算运单费用，只加入部分批次费用，遗漏普通附加费等。
2. 批次附加费用读取异常曾被捕获后返回零。
3. 收款时如果没有账单，会再次生成账单，容易使用与页面不同的数据。
4. 收款界面再次传入已计入账单的折扣，可能重复减免。
5. 确认状态、快照、账单主表、明细分开写入，存在部分写入成功的情况。

## 本次流程

- 单独确认／批量确认：从同一批次费用汇总创建快照与账单明细。一个客户的确认状态、快照、账单、明细在一个数据库事务中提交，失败则全部回滚。批量操作逐客户报告成功和失败。
- 确认后：客户“我的批次”和后台客户账单费用显示冻结的明细；已确认账单不随重新量尺或刷新快照改变金额。修改费用要取消确认、修改、重新确认。
- 客户钱包付款保留。客户钱包、后台钱包、批量扣款、EMT／现金均要求已存在对应账单，并核对显示金额、快照金额、账单金额及明细合计。支付不再生成账单，也不能追加折扣。
- 付款事务锁定账单并再次核验金额。重复付款返回已结清；线下收款记录与结算一同保存。
- 账单详情的批次账单付款／线下登记也走相同入口。非批次账单沿用原来的处理。
- 单运单生成、旧整批生成、商城计费没有改动。合并／拆分样例后续单独说明；已确认的新批次账单受冻结保护。

## 发布前事项

先在测试环境执行 `20260928200000_confirmed_batch_invoice_workflow.sql` 并验证，再发布对应代码。迁移依赖已有的 `settle_batch_customer_txn` 及此前箱／托盘归属迁移；若函数定义不符合预期，迁移会报错停止。

旧未付账单没有新版快照关联时会拒绝扣款，需要后台核对后取消确认、重新确认。重复有效账单、部分收款或已付款记录不能自动覆盖，需人工核对。此版本不修改历史账单、不执行真实扣款。

本地金额校验及相关回归测试通过。数据库事务函数尚未在实际 PostgreSQL 环境执行验证，不能将代码构建成功视为数据库迁移已通过。
