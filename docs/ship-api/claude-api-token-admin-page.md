## 3 页面入口和布局

建议路由 /admin/api-tokens，菜单名称“API 凭证管理”。具体 TanStack 文件名按项目路由规范落地，使用现有后台布局、表格、弹窗、按钮和提示组件，不引入第二套 UI。

页面顶部显示标题、简短说明和“签发新凭证”按钮。

说明文案：为合作方签发 API 访问凭证。密钥仅在生成时显示一次，后续只能撤销并重新签发。

第一版合作方固定为 ship。列表服务端查询必须固定或验证该范围；其他合作方记录不应在这个专属页面被误操作。

页面展示当前已配置 API 根地址。不让管理员在签发弹窗任意填写域名，也不把任意 Host 请求头直接拼成对外交付地址。优先复用可信公共服务地址配置；没有时显示“API 地址尚未配置”，允许保存新密钥但不要复制一个虚假或猜测地址。

不要写死示例域名或把 ship-cheap.com 当作我方 API 域名。

## 4 凭证列表模板

| 名称 | 合作方 | 权限 | 状态 | 创建时间 | 最近使用时间 | 操作 |
|---|---|---|---|---|---|---|
| ship 联调业务凭证 | ship | 线路、运单、客户资料 | 有效 | 实际时间 | 尚未使用 | 详情、撤销 |
| ship 管理端费用凭证 | ship | 运单查询、费用查询 | 已撤销 | 实际时间 | 实际时间 | 详情 |

状态从 is_active、revoked_at 推导：revoked_at 存在优先显示“已撤销”；否则 is_active=true 显示“有效”，false 显示“已停用”。

最近使用时间为空显示“尚未使用”。时间按后台现有时区方式格式化，不更改数据库时间语义。

详情包含凭证 ID、名称、partner_key、权限、创建时间、撤销时间、最近使用时间。不显示 token_hash，不提供“查看旧密钥”按钮。

第一版可提供名称搜索和状态筛选；数据量小时在前端筛选已授权列表即可。不把筛选当访问控制。

空列表显示“尚未签发凭证”。读取失败显示可重试提示；数据库缺表或未部署时不能伪装成空列表。

不要求填写客户号、销售账户、分级、线路价格、Supabase 密钥或手工 Token。

## 6 权限选项与预设

| 页面名称 | 实际 scope | 说明 |
|---|---|---|
| 查询线路及录单规则 | routes:read | 不包含我方结算价格 |
| 查询运单 | orders:read | 现有按国内单号查询 |
| 创建及待入库修改删除运单 | orders:write | 当前三种操作共用权限，不拆成假独立选项 |
| 更新客户资料 | customers:write | 显式更新 |
| 查看运输费用及费用明细 | orders:fees:read | 仅给管理端 |

业务对接预设：routes:read、orders:read、orders:write、customers:write，不含费用。

管理端费用查询预设：orders:read、orders:fees:read。若其确实也要录单，管理员可以显式增加其他权限，不能默认把费用预设变成全部权限。

勾选费用权限时必须同时有 orders:read；前端可以自动勾选并解释，服务端也校验这种组合。scope 去重；不接受未知字符串。

界面提示：费用信息仅供合作方管理端使用，合作方需要自行限制客户端展示。此提示不代替真实 API 的 scope 校验。

## 7 签发操作与结果弹窗

用户点击“生成凭证”后调用 issuePartnerApiToken。提交期间禁用按钮，避免双击重复签发；不要配置自动重试签发请求。

服务端成功响应中的 token 只在当前结果弹窗保留。弹窗显示凭证名称、合作方、权限、配置好的 API 根地址、完整 Token 和以下提示：

密钥仅显示这一次，请立即复制并安全保存。关闭后无法再次查看原密钥；丢失时请撤销该凭证并重新签发。

提供“复制密钥”“复制对接信息”“我已保存，关闭”按钮。密钥长字符串必须能完整选择和复制，不能把省略号文本复制给用户。

复制密钥只包含实际 Token。复制对接信息包含下列内容：

~~~text
合作方：ship
API 根地址：<当前环境实际配置的 HTTPS 地址>/api/partners/v1
Authorization: Bearer <本次实际生成的 Token>
权限：<本次实际授权权限>
说明：仅在合作方服务器端保存和调用。
~~~

复制动作由管理员主动点击触发，不自动发消息给 ship，不自动下载包含密钥的文件。剪贴板 API 失败时提供手动选择复制方式并明确提示。

关闭结果弹窗后清空前端内存中的明文，不写 localStorage、sessionStorage、URL、埋点、日志、持久化查询缓存或错误上报。生成响应是唯一返回明文的正常路径。

网络超时可能意味着凭证已经成功签发。提示管理员刷新列表核对，若新增记录的明文已丢失，应撤销该记录后重新签发，不能宣称生成失败、自动连发多个 Token 或尝试从哈希恢复明文。

## 8 撤销操作

有效凭证提供“撤销”按钮，点击后显示名称、合作方和权限摘要。

确认文案：撤销后，使用此凭证的 API 请求将无法继续通过鉴权。已创建的客户和运单保留，不受影响。是否撤销？

确认后调用 revokePartnerApiToken，成功刷新列表并显示“已撤销”。已撤销记录保留，不物理删除；不提供恢复同一密钥功能。

当前服务端撤销仅按 ID 更新，可能对不存在的 ID 返回成功。完善为：验证 UUID、验证属于 ship、检查实际匹配记录；未知记录返回明确错误；重复撤销同一记录可幂等成功，保留首次撤销时间和操作者。

后续使用该 Token 发起的新 API 请求应返回 401。已经通过鉴权且正在处理的请求不承诺中途取消。

重新签发应明确创建新 Token，不自动撤销其他有效凭证。管理员有意识地决定何时撤销旧凭证，避免意外中断合作方。

## 9 服务端权限和输入校验

只有 has_role 判定为 owner 的员工账号可访问和调用本页功能。隐藏菜单不构成权限保护，直接访问路由、调用 server function 也必须拒绝非 owner。

员工 owner 角色与 profiles.vip_level 中的 owner 客户分级完全不同；拥有该客户分级的人不能签发密钥。

目前 inputValidator 主要是 TypeScript 类型透传，开发时使用项目现有 Zod 等运行时验证方式补齐名称、partnerKey、scopes、UUID 校验。

此 ship 专属管理入口 partnerKey 在服务端固定 ship 或严格限定白名单，不能只依赖前端只读字段。若现有通用函数被其他合作方使用，应使用专属封装或兼容校验，不破坏已用通用功能。

所有数据库敏感读写继续通过已有 server-only 路径。partner_api_tokens 的现有 RLS 不得为了让页面直读而放开；客户端不能取得 service_role 密钥、token_hash 或跨合作方资料。

签发和撤销异常转为安全的用户提示，不把数据库错误、原始请求或生成的 Token 直接写入普通日志。

## 10 数据字段处理

第一版复用当前字段：

- id、partner_key、name、scopes。
- token_hash，只供服务端验证，不进入列表。
- is_active、created_at、created_by。
- revoked_at、revoked_by、last_used_at。

复用现有 generatePartnerApiToken 的密码学随机生成和 sha256Hex。不能用时间戳、用户名、UUID 拼出替代密钥。

不需要迁移即可完成基础页面。若核查发现实际部署库缺已有表，交付缺失迁移说明，不在生产环境擅自执行。

## 11 可选增强的完整边界

有效期和备注本次默认排除。若后续另行启用：

有效期需要 expires_at timestamptz 可空，签发时验证未来时间；鉴权每次检查到期并拒绝，列表显示已过期状态。仅显示到期日期而不拦截请求不算实现。

备注需要单独保存字段及长度限制，列表/详情读取。不要把备注偷偷拼进 token_hash 或作用于权限。

测试/生产切换需要真实环境配置和隔离，不是为 Token 新增一个标签就实现。不能让普通管理员从页面填写数据库地址、密钥或任意远程服务器。

这三项不会作为第一版验收缺项，也不能未经需求确认扩大成完整合作方管理平台。
