# ChatGPT EPLUS 只读连接测试记录

执行日期：2026-09-18。环境：china-to-canada-connect.lovable.app；ChatGPT 个人开发插件“EPLUS 客服测试”。不记录账号密码、订单号、客户资料或原始业务结果。

## 已观察结果

用户在 ChatGPT 发送：“确认我现在连接的是哪个 EPLUS 客户账号，然后查询我最近 3 个订单及物流状态。只查询，不修改任何资料。”

通过 ChatGPT 的 Tool call list 核实，依次有 6 次业务调用：

1. get_current_customer
2. list_my_orders
3. list_my_forwardings
4. get_my_forwarding
5. get_my_forwarding
6. get_my_forwarding

以上均为只读工具。本轮没有调用写入工具。身份查询返回 owner / customer，主角色为 owner。商城订单返回空列表；集运查询返回 3 条记录，随后查询其详情并汇总状态。输出带 CAD 标识，详情标记 payment_available_here=false。

## 后续只读测试

运营方确认可继续使用当前真实业务账号，管理员降权和隔离测试留待其完成权限调整后执行。

1. 询问已列出的一张运单的详细状态、轨迹及 ETA。实际调用 track_waybill，成功返回运单；回复明确说明没有轨迹节点和 ETA，不推断船舶位置或到港时间。本次未调用写入工具。
2. 询问当前可用线路和逐线路允运/禁运规则，要求缺失信息不推测。实际调用 list_forwarding_routes，direction=forward，返回 3 条线路、YW 仓及 CAD 标识。回复明确指出规则字段为空，不套用其他路线规则。本次未保存草稿、创建订单或调用其他写入工具。

发现的配置待核实项：一条路线的名称表示海运而 shipping_method 返回 air；返回的三条路线未提供允运/禁运说明。这些是查询结果中观察到的数据配置问题，未擅自修改。集运记录与对应运单还呈现不同付款状态；可能是不同业务层级，尚未核实映射，不能直接作为同步错误处理。

当前通过的是查询链路及缺失信息如实表达；路线配置的业务准确性、客户隔离、草稿/留言写入确认和完整审核录制仍未完成。
